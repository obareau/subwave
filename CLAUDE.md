# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

SUB/WAVE is a personal internet radio station: one Icecast stream, all listeners hear the same broadcast, AI DJ picks tracks and reads scripts between them. See `README.md` for the architecture diagram and rationale.

## Common commands

Three operator entry points, all driving the same compose files + `state/` layout: the **standalone `subwave` CLI** (single binary, no clone — default for new installs), raw `docker compose` (no-CLI alternative), and `npm start` (contributor convenience inside a clone).

```bash
# --- dev (Mac smoke test, requires git clone) ---
docker compose -f docker-compose.dev.yml up -d     # Broadcast (icecast2+liquidsoap) + Controller (tsx watch)
cd web && npm install && npm run dev               # web UI on :7700, separate process

docker compose logs -f controller        # prod default
curl http://localhost:7700/api/health    # liveness via Caddy edge (prod)
```

The CLI resolves its install location via `SUBWAVE_HOME` (priority: `--home` → `SUBWAVE_HOME` env → `~/.config/subwave/config.json` → cwd if it has a `docker-compose.yml` → `~/subwave` if it exists → error). The cwd fallback is what makes `cd subwave-repo && npm start` work with zero config.

There is no `/skip` endpoint — track-end is the only natural transition. Liquidsoap controls pacing.

**Compose files live at the repo root**, not under `docker/`. One root `.env` is the entire boot config surface — everything else lives in `state/settings.json`, managed by the wizard + admin UI.

**Dev hot-reloads; prod needs a rebuild.** In dev compose, `controller/src/`, `controller/scripts/`, and `radio.liq` are bind-mounted and the controller runs `tsx watch`, so edits restart in-place. In **prod** images `COPY` source at build time, so `restart` reruns the *same baked-in code* — changes need `up -d --build`.

```bash
docker compose -f docker-compose.dev.yml restart controller  # rarely needed — tsx watch handles src/** edits
docker compose -f docker-compose.dev.yml restart broadcast   # after radio.liq edits in DEV (bind-mounted)
docker compose up -d --build controller     # after controller/src/** in PROD
docker compose up -d --build broadcast      # after radio.liq / icecast.xml.template / Dockerfile.broadcast in PROD
```

`web` runs as a Next.js dev server (`npm run dev`) and hot-reloads in dev; prod builds the web image and needs a rebuild like the others.

**Lint is the merge gate; tests are not.** `controller/` and `web/` each expose `npm run lint` (`eslint . && tsc --noEmit`), and `mcp-subwave/` exposes `npm run lint` (`tsc --noEmit`); CI runs all three on every PR (`.github/workflows/lint.yml`, plus a theme-token mirror drift check on `controller`) and those jobs are what block a merge.

`controller/` also has a test suite — `npm test` (`scripts/run-tests.ts`) auto-discovers every `scripts/*.test.ts` and runs each as its own tsx subprocess, so a test that fails by `process.exit(1)` and one that fails by a thrown `assert` are caught the same way. **Dropping a `*.test.ts` file into `controller/scripts/` is the whole registration step** — no package.json edit. `npm test -- <substring>` filters to matching files. `web/` and `mcp-subwave/` have no tests. Since CI doesn't run any of this, run `npm test` yourself before pushing controller changes.

## Architecture

Four cooperating processes with **file-based IPC** through a shared `state/` dir (mounted at `/var/sub-wave` in containers). This is the load-bearing fact about how the system works — there is no socket or RPC channel between controller and Liquidsoap.

- **Controller → Liquidsoap**:
  - `next.txt` — controller writes one annotated track URI; Liquidsoap polls every 1.0s, drains, and `request.queue.push`es it.
  - `say.txt` — WAV path; polled every 0.5s, fed through `voice_queue`, **heavy-ducked** (`smooth_add p=0.25`). Station IDs, hourly time, weather, request intros.
  - `intro.txt` — between-track auto-DJ links; polled every 0.5s, fed through `intro_queue`, **light-ducked** (`smooth_add p=0.40`) so the song that just started stays audible under the voice.
  - `auto.m3u` — fallback playlist the controller rewrites every `AUTO_QUEUE_REFRESH_MINUTES` (default 60) for the current mood; Liquidsoap reloads on file change (`reload_mode="watch"`).
  - `liquidsoap_*.txt` (jingle_ratio, crossfade, opus_enabled, opus_bitrate, flac_enabled, aac_enabled, aac_bitrate, …) — tiny files written by `settings.update()`, read once at `radio.liq` startup. Changes need a Liquidsoap restart (controller triggers via `/restart-mixer` → telnet).
- **Liquidsoap → Controller / UI**:
  - `now-playing.json` — written from `music_meta.on_metadata(on_meta)`. The hook must stay on `music_meta`, the **pre-cross** handle captured before `music` is wrapped in `cross(...)`. Hooking the post-cross source fires twice per transition (because `dj_transition` passes `initial_metadata=` into both `fade.in` and `fade.out`), freezing the UI one song behind. `on_metadata` is used instead of `on_track` because `on_track` gets swallowed by source switches (request queue → auto playlist).
  - `jingle-playing.json` — `{filename, startedAt}` written when a jingle starts feeding the jingle rotate (issue #997). Jingles play outside the controller's voice serialiser (and `music_meta` is captured above the rotate, so the incoming track's metadata fires while the stinger is still in the cross buffer); `airVoice` (`broadcast/queue.ts`) reads this and holds every spoken segment until the stinger's window (start + clip length + crossfade) has passed. `jingleRatio: 0` disables jingles entirely (radio.liq skips the rotate; needs mixer restart like every ratio change).
  - `bed-playing.json` — `{filename, startedAt}` written when a track annotated `subwave_kind="bed"` starts (beds — an instrumental the DJ talks over BETWEEN songs, so a long link isn't talked over the song it's introducing). A bed is pushed into `dj_queue` like any other request but is NOT a song: `on_meta` branches on the annotation BEFORE its `title != ""` gate, so a bed never reaches `now-playing.json` and never pushes an ICY title. That silence is also why the marker exists — the controller learns "the bed is on air, air the link now" only from this file (`queue.onBedStarted`, read on the same 1.5s now-playing tick). Same shape and rationale as `jingle-playing.json`.
- **Controller → Web UI**: HTTP. `useStationFeed` (`web/hooks/useStationFeed.js`) polls `/now-playing` + `/state` every 5s.
- **Controller state**: `session.json` — the live DJ session (chat-history JSON, see `broadcast/session.js`); archived to `state/sessions/<id>.json` on roll. Controller-internal, not read by Liquidsoap.
- **Browsers → Icecast**: direct `<audio>` on `…/stream.opus` (Blink) or `…/stream.mp3` (everything else). `usePlayer` (`web/hooks/usePlayer.ts`) probes `canPlayType('audio/ogg; codecs=opus')` once and upgrades to Opus only on a definitive `'probably'` **and** non-iOS, non-Firefox (both choke on Icecast's chained-Ogg page boundary at a crossfade — issues #168/#215). Opus is **off by default** (see Liquidsoap step 9), so the probe usually 404s and the hook falls back permanently to MP3 for the session. MP3 is the universal floor (Sonos, hardware radios, car receivers, pre-iOS-17 Safari). `useMediaSession` wires lock-screen / headphone / CarPlay controls, artwork from the controller's `/cover/:id` proxy.

### Docker layout

Three compose files at the repo root, three deployment shapes:

- **`docker-compose.yml`** — prod single-host with bundled Caddy. **The default.** `broadcast` (icecast2+liquidsoap), `controller`, `web`, `caddy`. **Only Caddy binds a host port** (`${CADDY_PORT:-7700}:80`); the rest are internal. State path `${STATE_DIR:-./state}`. Cloudflare terminates TLS (`auto_https off`). `controller` is forced `NODE_ENV=production` → admin gate mandatory. Configs baked into images, not bind-mounted.
- **`docker-compose.byo.yml`** — prod for hosts with their own Traefik/nginx/Caddy. Same as default minus bundled Caddy; `web`/`controller`/`broadcast` bind host ports (`${WEB_PORT:-7700}`, `${CONTROLLER_PORT:-7701}`, `${ICECAST_PORT:-7702}`). The web image is baked for same-origin `/api` + `/stream.mp3`, so the operator's proxy must replicate `docker/Caddyfile`'s route table on one hostname; split hostnames need a web rebuild with `NEXT_PUBLIC_*`.
- **`docker-compose.dev.yml`** — Mac local smoke-test. Broadcast + Controller only (web runs separately via `npm run dev`). State `./state`. Bind-mounts `radio.liq`, `sounds/`, `controller/src` so dev edits need no rebuild.

**Optional `tts-heavy` profile** in all three composes — a `tts-heavy` sidecar (`profiles: ["tts-heavy"]`, does NOT start unless `docker compose --profile tts-heavy up -d`) hosting Chatterbox + PocketTTS over HTTP on the shared `/var/sub-wave` volume. Off by default keeps the install lean. It is **TTS-only** — acoustic analysis was moved out into the standalone `analyzer` service (see below).

**Default-on `analyzer` service** — the acoustic-analysis sidecar (`subwave-analyzer` image, `docker/Dockerfile.analyzer` + `docker/analyzer/server.py`). **Starts by default** in all three composes (no profile gate — like controller/web); only `tts-heavy` (voices) stays opt-in. It's the librosa (+ optional CLAP + Demucs) analyzer **split out of tts-heavy**: bpm/key/intro/loudness always, plus **outro analysis** on every tier (last ~20s of each *complete* file → `tracks.outro_json`: fade-vs-cold ending, tail LUFS/tempo/bars; a byte-capped download skips it — the completeness flag rides the analyze request). The outro is what makes transitions ending-aware: `queue.applyMixTransition` stamps each DJ-mode track's OWN exit canvas from its measured ending via `mix.endingCrossSecondsFor` (a fade rides out 8–12s, a cold end cuts ~4s; washout/loop overwrite it) — the per-track answer to #749, which blocks the pair-sized `crossSecondsFor` from ever being applied — and a measured fade vetoes the `chop` effect (`effectAllowedFor`). **Vocal-aware transitions** (heavy tier, vocal detection on): the outro window gets its own Demucs pass → `outro.vocalRanges` (absolute ms, `[]` = instrumental tail; backfill widened via the `tail_vocal` capability flag so stale analyzer images never churn; lyric-decided tracks skip the tail Demucs pass like the head one — their tail ranges are clipped from the synced-lyric timing instead, `lyric-vocal.clipRangesToTail`) — a sung fade pulls its exit canvas to the 8s floor (`Analysis.vocalTail`), a sung ending vetoes `chop`, and a *measured* first-vocal entry under 2.5s drops the DJ link outright (`enforceIntroBudget` — see `docs/stem-transitions-research.md`); "sounds-like" embeddings (multi-window CLAP — start/mid/late windows averaged, so quiet intros don't misrepresent the track), vocal ranges, and the CLAP **text tower** (`POST /embed-text`, capability-flagged in `/health`) are the heavy tier. Text and audio vectors share one 512-d space, which powers the picker's `searchBySound` tool (describe a sound in words → audio KNN) and zero-shot audio moods (`music/audio-moods.ts`: mood-vocab prompts scored against stored audio vectors at the end of every analysis pass → `tracks.audio_moods`, blended into `songsByMood`/`trackMoods`; vocab/prompt changes re-score via `mood_vocab_hash`). **Two published flavours**: `subwave-analyzer` — **LEAN, multi-arch** (~1.1GB — librosa + ffmpeg, no torch — the default everyone pulls), `WITH_CLAP=0 WITH_DEMUCS=0`; and `subwave-analyzer-heavy` — CLAP+Demucs baked (~1.9GB, amd64-only), `WITH_CLAP=1 WITH_DEMUCS=1`. **Opt-in switch is `ANALYZER_HEAVY=1` in `.env`** — the compose `analyzer` service resolves `image: …/subwave-analyzer${ANALYZER_HEAVY:+-heavy}:…` and its `build.args` key off the same var (so pull and local build agree). No `platform` pin (lean is native arm64; heavy on arm64 needs `DOCKER_DEFAULT_PLATFORM=linux/amd64`). Uses the **same `analyze_worker.py`** as the offline CLI (single source of truth). The controller resolves its analysis backend from `config.analyzer.urls` — **`ANALYZE_URL`** (`music/analyzer.ts` probes `/health`), then a local venv (`ANALYZE_PYTHON`). tts-heavy is TTS-only now and is **not** an analysis backend (no `TTS_HEAVY_URL` fallback). **AIO (`Dockerfile.aio`) bundles the analyzer in-process** (local venv, `ANALYZE_PYTHON` + `HF_HOME` under the state dir) rather than a service; `subwave-aio` is lean, `subwave-aio-heavy` bakes CLAP+Demucs. The analyze worker lives in the analyzer image(s) and the AIO.

**Image-first pulls, source-build fallback.** Every service references `ghcr.io/perminder-klair/subwave-{caddy,broadcast,controller,web,tts-heavy,analyzer}:${SUBWAVE_VERSION:-latest}` alongside a `build:` block. `up -d` pulls; `build && up -d` rebuilds. Publishing via `.github/workflows/publish-images.yml` on tag pushes (`v*`).

**Auto-generated Icecast secrets.** The broadcast entrypoint (`docker/broadcast-entrypoint.sh`) resolves `ICECAST_*_PASSWORD`: env override → persisted `state/icecast-secrets.env` → freshly generated hex, then writes back and exports into liquidsoap's env. icecast + liquidsoap share one container, so there's no cross-container handshake. To rotate: delete `state/icecast-secrets.env` and restart `broadcast`.

**Private station mode (#478).** `settings.privacy` holds two independent locks over ONE shared `password`: `privatePlayer` (the web player pages ask for it before rendering — shell-level in `PlayerShell`, rides `/state`, applies live) and `listenerAuth` (Icecast listener auth on every stream mount). Either lock being on requires a password — `settings.update()` throws otherwise, because a lock with no password behind it either fails every listener closed or renders a prompt nobody can satisfy. Listener auth uses Icecast **URL auth**, not htpasswd: `settings.update()` writes `state/icecast_listener_auth.txt`, and the broadcast entrypoint (+ AIO supervisor's `render_icecast()`, re-run on every pair relaunch) renders per-mount `<authentication type="url">` blocks pointing at `POST /listener-auth`. External clients send basic auth (`user:pass@`), the web player rides `?auth=` on the mount query (Icecast forwards the query string in the auth callback; browsers can't basic-auth an `<audio>` element). **Two endpoints, opposite failure modes — do not merge them**: `POST /listener-auth` (Icecast) fails OPEN when `listenerAuth` is off, covering the window where icecast.xml still carries the auth blocks but the setting is already off; `POST /station-auth` (the web gate, rate-limited) fails CLOSED, because `privatePlayer` can be on while `listenerAuth` is off and reusing the Icecast decision there would accept any password. Both live in `util/listener-auth.ts`, pinned by `scripts/listener-auth.test.ts`. Toggling `listenerAuth` needs a mixer restart (rides `requiresRestart`); password changes apply live. `/listen.pls`/`/listen.m3u` 403 while auth is on. Settings UI lives in the **Station** section. See `docs/private-station.md`.

**Public persona disclosure.** `settings.privacy.publishPersonaSouls` (default `false`) sits in the same block but is **a disclosure toggle, not a lock** — it takes no part in the password invariant above, needs no restart, and applies live. It governs the ROSTER-WIDE public reads: `GET /schedule`'s persona index and `GET /personas`. Those always publish `id`/`name`/`tagline`/`avatar` (and each show's `guestPersonaIds`, resolved against the live roster so a deleted guest vanishes); a persona's `soul` rides only when the toggle is on, because a soul is the persona's **system prompt**, not a written bio, and these reads hand over every persona at once. When off the key is **absent, not empty**, so a client can tell "not published" from "published but blank" (`/personas` also reports `soulsPublished`). `GET /dj` is deliberately **out of scope** — it has always published the ON-AIR persona's soul, one at a time, and gating it would break existing public clients. The shape + rule live only in `util/public-persona.ts` (never inline in the route), pinned by `scripts/public-persona.test.ts`. Never widen the shape to TTS config, skills, or the behaviour dials.

**Single config surface.** Three required root `.env` vars boot the stack: `ADMIN_USER`, `ADMIN_PASS`, `SITE_URL`. Everything else is collected by two converging wizards — `npm run setup` (terminal, `cli/src/commands/setup.ts`) and `/onboarding` (browser, `web/components/onboarding/*` → `controller/src/routes/onboarding.ts`). Both persist to the same layer: Navidrome creds + setup timestamp → `state/setup-config.json`; cloud LLM/TTS keys → `state/secrets.env` (mode 0600, sourced on boot via `setup/secrets.ts`); everything else → `settings.update()` → `state/settings.json`. **Env always wins**; wizards only fill gaps. `setup/firstRun.ts` decides `needsSetup` (no Navidrome creds from env or config); `/state` exposes it so the player + AdminShell redirect a fresh operator to `/onboarding`.

The shared `/var/sub-wave` mount in **both** Broadcast and Controller is what makes the file-based IPC work — they must always map to the same host path.

### Jingles

`state/jingles.m3u` is empty by default. Run `scripts/generate-jingles.sh` after the stack is up — it `exec`s into the controller, pipes text through the configured TTS engine, writes WAVs into `${STATE_DIR}/jingles/`, rewrites the M3U. ## Working on this codebase

- **Queue/playback path**: `queue.drainToLiquidsoap()` is the single writer of `next.txt` (+ request-intro `say.txt`); `queue.announce()` is the single writer of scheduled `say.txt`/`intro.txt`. Request-intro WAVs are written ~250ms before the track URI so the 0.5s voice poll picks them up first. Poll intervals (1.0s queue, 0.5s voice) are the upper bound on perceived latency. **Pair-aware drains** (`transitions.pairDrain`, default on, **DJ-mode personas only** — `queue.pairDrainActive()`, `broadcast/drain-policy.ts`): picks are HELD unsent until their successor is queued behind them (the deadline routine in the watcher tick picks it ~120s before the on-air track's effective end, `min(duration, cue_out)`, with a failure-retry cooldown of `DEADLINE_PICK_COOLDOWN_SEC`; hard fallback ~45s drains with intrinsic stamps), which is what lets `applyPairStamps` finally apply the pair-sized `crossSecondsFor` (#749) and lets stem blends insert. A successor of ANY kind releases the hold (a request IS the successor arriving — FIFO is never inverted); unknown clock (boot/recover/untracked auto) or a non-DJ persona drains eagerly, byte-for-byte the old behaviour. **Stem blends** (`transitions.stemBlends`, opt-in; `broadcast/stem-blend.ts` + worker `render_transition`): at a pair drain, a cache-hit-only render mixes the outgoing tail stems × incoming head stems (`state/stems/`, written during analysis when `audio.stemCache` is on) into a clip that airs between them — outgoing cues out at the blend start, the clip carries the INCOMING track's identity (now-playing flips at blend start; `lastSeenKey` dedups the real fire; `subwave_clip="1"` keeps telnet rid helpers honest), incoming cues in past its pre-mixed head. Any miss → plain pair-aware crossfade. Clips sweep after 1h (clips still queued for an unaired seam are exempt — `queue.pendingClipPaths()`); the stem cache is byte-budget LRU (`audio.stemCacheGb`, 1–500 GB, edited in Settings → Transitions), and tail stems carry a `tail-meta.json` alignment sidecar (exact decoded tail offset — the render treats stems without it as a miss). **The stem cache backfills** like the CLAP/vocal scopes: `tracks.stems_at` (schema v17) stamps every stem ATTEMPT, `db.needsStemsIds()` is the fourth widening in `runAnalysisPass`, so turning the cache on for an already-analysed library fills in over successive resumable passes instead of needing a `--re-analyze` (which wipes every vector and can't resume). The stamp records the attempt, **not disk presence** — the LRU sweep evicts dirs by design, so a presence-based scope would re-separate every evicted track forever on any library bigger than the budget; a miss at seam time just falls back to a plain crossfade. The widening is capped at `stemCache.headroomTracks()` (what the budget can still hold, ~25 MB/track) and logs what it left behind, so a big library doesn't burn hours of Demucs on tracks the sweep evicts minutes later. Pinned by `scripts/stem-backfill.test.ts`.
- **`radio.liq` `on_metadata`**: keep it on `music_meta`, the pre-cross handle (post-cross fires twice; `on_track` gets swallowed by source switches). See Architecture.
- **Crossfade**: keep fade duration equal to the cross buffer (`d = crossfade_duration()`, `fade.out(d)` / `fade.in(d)`). Shorter fades inside a fixed buffer let the outgoing track play full while the incoming ramps, summing to +6 dB (audible doubling). Vary the buffer length instead.
- **Listener buffer / live-edge offset (#1114)**: Icecast bursts `settings.stream.bufferSeconds` (default 22s) of already-broadcast audio on connect, so **every listener sits that far behind the live edge for their whole connection**. Two consequences that must stay in sync. (1) `<burst-size>` is a BYTE count, so it's computed **per mount** — `bufferSeconds x that mount's bitrate x 125`, rendered as one `<mount>` block per stream mount by `docker/broadcast-entrypoint.sh` (and the AIO's `render_icecast()`, kept in lockstep), reading `liquidsoap_stream_buffer_seconds.txt` + the per-encoder bitrate files from the state dir; FLAC is VBR so its depth uses a ~900kbps estimate. Never collapse this back to one global figure: the same 528 KB that is 22s of 192k MP3 is ~43s of 96k Opus and ~6s of FLAC (the post-#1114 "Now Spinning runs behind" report). Each mount's `<queue-size>` is 4x its burst (floored at 2 MB) and must stay comfortably above it or clients get evicted the moment they fall behind their own primed buffer. (2) Every timestamp the controller publishes is stamped at the **live edge** (`radio.liq`'s pre-cross `on_metadata`), so listener-facing players shift into listener-time — `useStationFeed` holds the track switch until the audio is actually audible and `trackStartedAt` carries the offset (it can briefly sit in the future; `useElapsed` clamps at 0). The web player prefers its own **measured** lag (`usePlayer.getListenerLagMs`: `buffered.end − currentTime`, exact for whatever mount/connection is playing) and falls back to the advertised `stream.bufferSeconds` from `/now-playing` when the tab isn't the thing playing the audio. Operator surfaces (admin dash, MCP) intentionally keep live edge. Changing the depth needs a broadcast **container** bounce, not just a mixer restart — though the telnet `restart` achieves it anyway, since icecast and liquidsoap share a container the entrypoint `wait -n`s on.
- **Real listener IPs / trusted proxies**: Icecast's only peer is the edge, so admin → Listeners shows the proxy's container IP unless `<x-forwarded-for>` names that proxy. Rendered into the template's `<!--@TRUSTED_PROXIES@-->` marker by `docker/broadcast-entrypoint.sh` and the AIO's `render_icecast()` — the **third** thing those two must keep in lockstep, alongside the per-mount burst/queue and the listener-auth blocks. Two icecast-KH facts pin the design: it matches an **EXACT IP** (a CIDR is accepted and then silently never matches, so no subnet shorthand), and it reads the **left-most** entry of the chain (the real client, even though Caddy appends its own peer). Source order is `ICECAST_TRUSTED_PROXY_IPS` (explicit, wins) → DNS for `ICECAST_TRUSTED_PROXY_HOSTS` (default `caddy`). The DNS path is **deliberately best-effort and misses the first cold boot** — caddy `depends_on` broadcast being healthy, which needs icecast already serving, so the name cannot resolve at render time (measured: ~6s unresolved); every later restart picks it up. A miss degrades to the old behaviour (proxy IP shown), never to a wrong IP, so nothing downstream handles a half-applied state. The AIO trusts loopback outright (Caddy is in-container). Malformed entries are dropped rather than interpolated — invalid XML here would turn a cosmetic setting into a station that won't boot. Counting still must NOT key on IP (`groupConnections`): the header may be untrusted, and one NAT is many listeners.
- **Ducking**: stick with `smooth_add`. An RMS sidechain follower drove `music_bus` to silence (`f38a9af`). `smooth_add` is gated talkbax — it cares only whether the channel has signal, not how loud.
- **TTS**: callers go through `tts.speak(text, {kind})`, never the engine modules. `tts.js` handles per-kind override + automatic fallback. The Kokoro worker path defaults to `/app/scripts/kokoro_worker.py`; set `KOKORO_WORKER` for non-default layouts.
- **Subsonic**: keep using `getAnnotatedUri` for anything going to Liquidsoap — raw URLs lose metadata until ID3 arrives, and the `on_metadata` hook needs `subsonic_id` for `/cover/:id` artwork.
- **Genres are multi-value**: `subsonic.songGenres(song)` is the single ingest normaliser (OpenSubsonic `genres: [{name}]` array → `string[]`, legacy scalar fallback). library.db stores `genres` as a JSON array; the scalar `genre` column is GENERATED (genres[0], indexable) — write `genres`, never `genre`. Matching is any-of via `show-filter.ts trackGenres/genreMatches`; LLM-facing shapes carry all tags comma-joined in the `genre` field. **Genre matching is one-directional**: a track's tag may REFINE the show's genre (a "Punk" show admits a `Punk Rock` track) but never broaden it (a "Pop Punk" show rejects a plain `Pop` track), and containment is word-boundary aligned so a "Rap" show doesn't pull `Trap`. The reverse direction is what let strict shows leak broad tags — don't reintroduce it. Note the resolver `subsonic.resolveGenreName` is still deliberately loose both ways: it maps free text to a real library tag for listener requests and server-side fetches, so a show whose genre isn't a library tag can still broaden there (see issue for the fetch-hint/match-target split).
- **Era years (#842)**: a track's era is judged by `show-filter.resolveEraYear`, never raw `year` — the resolved `original_year` wins (walk-time album `originalReleaseDate` on non-compilation albums; MusicBrainz phase-0 enrichment for compilation tracks), and a **compilation's plain `year` is untrusted** (it's the compilation's own release date, so unresolved comp tracks read as unknown-year and drop from era windows). SQL-side era filters (`library-db.filter` yearFrom/yearTo, seed decade bucketing) mirror the same precedence — keep JS and SQL in agreement. `music/musicbrainz.ts` is keyless but hard-throttled to 1 req/s with a descriptive User-Agent (MB policy) — don't widen it; misses are stamped (`original_year_checked_at`) so passes never re-query them.
- **LLM**: calls go through the AI SDK via the `llm/sdk.js` primitives; `matchRequest` + pool picker use `djObject` (Zod-validated, no manual JSON parsing). Default provider is the homelab Ollama box — reliable but maybe slow; **don't add aggressive retry**. Adding a provider: extend `LLM_PROVIDERS` in `settings.js`, add a builder case in `llm/internal/provider/registry.ts`, and a descriptor in `llm/internal/provider/capabilities.ts` (thinking knob + object strategy); call sites never name a provider, and per-provider quirks live ONLY in `capabilities.ts`.
- **Daily token budget** (`settings.llm.dailyTokenCap`, default `0` = off): the running per-UTC-day token tally lives in `llm/internal/telemetry/budget.ts` (incremented from the single `record()` chokepoint in `telemetry/log.ts`, the same `ok && usage.total` guard as the lifetime ticker; seeded once at boot from today's `events-*.jsonl` so a restart resumes the count). The pure `budgetMode()` (`core/pure.ts`, unit-pinned) maps `{used, cap, softPct}` → `normal | soft | hard`; **policy lives only in `broadcast/dj-budget.ts`** (the call-site gates), never inline. Tiers: `soft` (≥`budgetSoftPct`%) forces the cheap pool picker and mutes optional segments (links, station IDs, hourly, weather/news/etc.); `hard` (≥cap) makes **no** model call — `runTrackEvent` returns early so Liquidsoap coasts on the LLM-free `auto.m3u` (music never stops). Listener requests stay exempt through the hard cap unless `llm.exemptRequests` is off. Manual `/dj/segment` command routes (the gate-free `runStationId`/`runHourlyCheck`/`runLink` runners) are intentionally **not** budget-gated — an explicit operator action always fires.
- **Station voice switch** (`settings.tts.enabled`, default `true`): `false` makes the station **music only** — no links, idents, hourly checks, skill segments, banter, persona mic-passes, programme beats or spoken request intros. **Policy lives only in `broadcast/voice-policy.ts`** (`autoVoiceAllowed()`, the call-site gates), never inline — same split as `dj-budget.ts`, and the gates sit at the same points those do. The gate is **before generation, not at `speak()`**: gating the dispatcher would still have the LLM write every script and throw it away, so instead `dj-gate.shouldFire()` returns false for every kind (above the frequency ladder — it's not a cadence), `skillsTick`/`ensurePlan`/`maybeRunIntro`/`featureTick`/`outroTick`/`runPersonaHandoff` stand down, `runTrackEvent` forces `wantLink=false` (the agent path's event prompt orders silence, the pool path skips `generateLink`), the request agent's contract drops its intro field (`requestSchema`), and `routes/request.ts` skips `generateIntro` outright. `queue.airIntro()` carries a plain drop as a backstop for items queued before the flip (their WAV render is skipped at drain too; flip back on before the track airs and `airIntro` renders from the script). **Picks keep running** (the stream needs a next track) and **listener requests are still honoured** — track queued, text ack returned, just no spoken intro. Two deliberate non-inclusions: **jingles** are pre-rendered WAVs on Liquidsoap's own rotate, silenced by `jingleRatio: 0` (mixer restart) rather than this switch; and **manual `/dj/segment` triggers still fire**, the same exemption they hold from the frequency gate and the LLM hard cap. Applies live — no restart, no mixer bounce. Absent/non-boolean coerces to ON so an upgrade is byte-identical. Pinned by `scripts/voice-policy.test.ts`. Distinct from per-persona `frequency: 'silent'`, which is per-persona and still speaks request intros, programme beats and manual triggers.
- **DJ persona**: `settings.dj.souls` is an array (1–10); `djSystem()` picks one at random per call. Legacy `dj.soul` string is migrated on load. Emptying the array falls back to seeded `DJ_SOULS`.
- **Station house rules** (`settings.djHouseRules`, #1182, default `''` = off): the one operator block appended to **both** prompt paths — `renderDjPrompt` (scripted talk) AND `agentPersonaPreamble` (pick/request/segment agents), which the `djPrompt` template never reaches. For path-agnostic correctness rules (TTS control tags, "spell out numbers", locale orthography); the agent-side framing scopes them to spoken fields so ids/reasons stay untouched. Edited in the System prompt modal on `/admin` Personas; empty keeps every prompt byte-identical. Pinned by `scripts/house-rules.test.ts`.
- **Guest co-hosts** (`shows[].guestPersonaIds`, max 3): while a guest show is on air, standalone segments (station ID, hourly, skill segments, manual link) rotate speakers via `settings.pickOnAirSpeaker()` (host ~60%) — the speaker persona rides through the generator prompt AND `queue.announce({persona, meta:{personaId}})`, so the voice, the prompt seat (`settings.onAirRosterClause`), and the session attribution always agree. **Track picks + their tied intros stay with the HOST** (the pick agent reads `session.windowMessages()` from the host's perspective); gating (frequency, capability ownership) is also host-keyed so who speaks never changes how often the station talks. `shows[].banter` (opt-in, needs guests) airs scripted multi-voice exchanges at :20/:50 (`dj-gate` `'banter'`: quiet=never, moderate=:20 only): one `generateBanter` `djObject` call writes the whole exchange, `queue.announceExchange()` renders every line's WAV first (all-or-nothing), then airs them back-to-back through the serialized `airVoice` chain — no audio mixing anywhere.
- **Programmes** (`shows[].programme`, opt-in; optional `shows[].segmentSkill` pins the feature): the show airs as a produced episode — intro at the top, one feature beat per hour (station-minute :35–:39 window), outro in the final hour's closing minutes (station-minute :55+) (`broadcast/programme.ts`; a single `*/5` cron dispatches on `dueBeat()`'s STATION-zone minute — fixed process-minute crons land mid-show on :30/:45-offset zones like IST; manual `runProgramme*` runners in `scheduler.ts`). Coherence comes from a per-episode **producer plan** (one `generateProgrammePlan` `djObject` call at session start: angle, per-hour feature topics, intro/outro notes) stored ON the session (`session.attachProgramme`); beats are marked aired BEFORE generating (the `markHandoffAired` idempotency pattern) so restarts never double-air. Plan-call failure → `fallback`: beats still air from the raw topic brief. Collision rules: the intro replaces the hourly check in hour one (and on a persona-change boundary the handoff **greeting** doubles as the intro — `episodeAngle` rides into `generateHandoffGreeting`; the standalone intro is skipped); `skillsTick` stands down for the whole programme (`programme.onAir()`); idents/banter keep their slots. The feature runs through the forced segment director (`runCapability(kind, ctx, {brief, persona})`) so it gets real data; a stale/absent kind falls to straight talk (`generateProgrammeFeature`). Guest shows open/close with multi-voice exchanges (`generateProgrammeExchange` → `announceExchange`). Pure arc helpers (`showSpan`, `planFeature`) live in `broadcast/programme-pure.ts`, pinned by `scripts/programme.test.ts`.
- **Festivals**: operator-editable via admin → Settings → Festivals (`settings.festivals`, validated by `validateFestivalsStrict`; seeded from `FESTIVAL_DEFAULTS` in `settings.ts` only when the key is absent — an emptied list stays empty). Fixed month/day schema, so lunar holidays (Easter, Eid, Lunar New Year) shift year-to-year and need per-year entries. `windowDays` spans month/year boundaries (`getFestivalContext` compares real dates).
- **Multi-station profiles**: `state/stations/<id>/` + `stations/active.json` decide the ACTIVE station dir, resolved once per boot in four places — `config.ts` (`STATE_DIR` = resolved dir, `STATE_ROOT` = root), `radio.liq` (`SUBWAVE_STATE_DIR` env), `docker/broadcast-entrypoint.sh`, and the AIO supervisor (kept in lockstep). No `stations/` dir → single-station, everything at the root as before. Switching = pointer write + mixer restart + controller `process.exit` (docker restart policy reboots both against the new dir) — never hot-swap state paths in-process. Only `icecast-secrets.env`, `hf-cache`, `analyze-tmp` stay install-level at the root (`conversionAction` in `stations/pure.ts` is the classifier; new root-level state files must be classified there and in `duplicateAction`). State files holding **absolute paths** must be re-derived at boot rather than trusted — `jingles.m3u` is the one such file today (`ensureDefaultIdent` rewrites it every boot so conversion/duplicate can't leave it pointing at a moved dir).
